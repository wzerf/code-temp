# Setup — Kotlin (KSP)

How to wire easy-query into a Kotlin project. Kotlin uses **KSP** for proxy
generation — **not KAPT**. The runtime API is identical to Java; only the
build setup and the lambda surface differ.

If the problem is "cannot find `UserProxy`", "proxy not generated", or KSP
does not appear to run, start with
`proxy-generation-troubleshooting.md` first, then return here for the concrete
Gradle wiring.

## When to use / not

Use for a Kotlin project (Gradle). For plain Java see `setup-java.md`; for Spring Boot see
`setup-spring-boot.md`. The query/write/transaction DSL itself lives in `query.md` / `write.md` /
`transaction.md` and applies to Kotlin too.

## 1. Gradle build (KSP)

```kotlin
plugins {
    kotlin("jvm") version "1.9.21"
    id("com.google.devtools.ksp") version "1.9.21-1.0.15"   // KSP version is paired with the Kotlin version
}

repositories { mavenCentral() }

dependencies {
    implementation(kotlin("stdlib"))
    implementation("com.easy-query:sql-core:3.2.14")
    implementation("com.easy-query:sql-mysql:3.2.14")        // dialect: pick one (sql-h2 / sql-pgsql / ...)
    implementation("com.easy-query:sql-api-proxy:3.2.14")    // the strong-typed proxy API
    ksp("com.easy-query:sql-ksp-processor:3.2.14")           // ★ KSP processor — generates the proxy classes
    implementation("com.mysql:mysql-connector-j:9.2.0")
    implementation("com.zaxxer:HikariCP:3.3.1")
    testImplementation(kotlin("test"))
}

kotlin {
    jvmToolchain(17)
    // Add the KSP-generated sources to the compile path so IntelliJ can resolve the *Proxy classes.
    // Without this, `gradle build` still works but the IDE shows the proxy types as unresolved.
    sourceSets.main {
        kotlin.srcDir("build/generated/ksp/main/kotlin")
    }
}
```

The proxy classes are generated under `build/generated/ksp/main/kotlin`. If a `*Proxy` type cannot be
resolved: confirm the `ksp(...)` dependency is present, run a build, and confirm the `srcDir` line above.

## 2. Entity (Kotlin)

A normal class or a `data class` works. Annotate with `@Table` + `@EntityProxy` and implement
`ProxyEntityAvailable<Entity, EntityProxy>`. The `TopicProxy` referenced here is generated by KSP.

```kotlin
package com.test.entity

import com.easy.query.core.annotation.Column
import com.easy.query.core.annotation.EntityProxy
import com.easy.query.core.annotation.Table
import com.easy.query.core.proxy.ProxyEntityAvailable
import com.test.entity.proxy.TopicProxy   // generated by KSP into <pkg>.proxy

@Table("t_topic")
@EntityProxy
class Topic : ProxyEntityAvailable<Topic, TopicProxy> {
    @Column(primaryKey = true)
    var id: String? = null
    var stars: Int? = null
    var title: String? = null
}
```

## 3. Initialize EasyEntityQuery (plain Kotlin, no Spring)

```kotlin
package com.test

import com.easy.query.api.proxy.client.DefaultEasyEntityQuery
import com.easy.query.core.bootstrapper.EasyQueryBootstrapper
import com.easy.query.core.logging.LogFactory
import com.easy.query.mysql.config.MySQLDatabaseConfiguration
import com.test.entity.Topic
import com.zaxxer.hikari.HikariDataSource

fun main() {
    val dataSource = HikariDataSource().apply {
        jdbcUrl = "jdbc:mysql://127.0.0.1:3306/easy-query-test?serverTimezone=GMT%2B8&characterEncoding=utf-8&useSSL=false&allowMultiQueries=true&rewriteBatchedStatements=true"
        username = "root"
        password = "root"
        driverClassName = "com.mysql.cj.jdbc.Driver"
        maximumPoolSize = 20
    }
    LogFactory.useStdOutLogging()

    val easyQueryClient = EasyQueryBootstrapper.defaultBuilderConfiguration()
        .setDefaultDataSource(dataSource)
        .useDatabaseConfigure(MySQLDatabaseConfiguration())   // dialect — match your `sql-*` artifact
        .build()
    val entityQuery = DefaultEasyEntityQuery(easyQueryClient)  // this is your EasyEntityQuery

    val list = entityQuery.queryable(Topic::class.java)
        .where { it.id().eq("123") }
        .toList()
}
```

Note the Kotlin call uses `Topic::class.java` (not `Topic.class`) and a trailing-lambda `where { it... }`.

## 4. Optional: infix DSL (Kotlin only)

easy-query ships Kotlin infix extensions so you can write `it.id eq "123"` instead of `it.id().eq("123")`.
This is purely syntactic sugar; both forms compile to the same query. Define/enable the infix functions
(shipped in the proxy module) and then:

```kotlin
val list = entityQuery.queryable(Topic::class.java)
    .where { it.id eq "123" }
    .toList()
```

If you are unsure whether infix is set up in the project, prefer the explicit `it.id().eq("123")` form —
it always works.

## Common mistakes

- Using **KAPT** for Kotlin — this project's Kotlin path is **KSP**. Don't add the kapt plugin.
- Forgetting the `kotlin.srcDir("build/generated/ksp/main/kotlin")` line → proxies unresolved in the IDE.
- KSP version not matching the Kotlin version (the `x.y.z-a.b.c` suffix is Kotlin-version-specific).
- Passing `Topic.class` (Java) instead of `Topic::class.java` (Kotlin).
- `@EntityProxy` is required to trigger KSP generation. Add
  `ProxyEntityAvailable<Entity, EntityProxy>` when the project uses that
  entity-side typed contract; it is not itself a generation switch.
